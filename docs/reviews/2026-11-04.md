# Review 2026-11-04 — findings, scores, and the plan for them

Four read-only reviewers over the whole app at 0.5.4 (`7a5f295`): security,
frontend bugs, backend bugs, and style/maintainability. Each scored its own
findings. A skeptical pass then re-checked the higher-scored claims against the
source and set the scores below (0–10: 8–10 is real data loss or an
exploitable hole, 3–7 is minor or a hardening/maintainability gain, and
anything ≤ 2 is a nitpick).
Baseline: `npm run check` 35/35, `npm run lint` and `tsc` clean, `cargo test`
21/21, `cargo clippy -D warnings` clean.

**No exploitable security hole was found.** A hostile drawing, library, theme or
link cannot run script or reach the Rust commands. Only BE-1 was reproduced in
the release binary. The rest are traced through `src/`, `src-tauri/` and the
Excalidraw 0.18.1 bundle, so every fix starts by reproducing its finding where
that is possible.

## Findings, by score

| ID | Score | Where | Finding |
|---|---|---|---|
| FE-1 | 7 | `scene.ts:11`, `document.ts` dirty checks | The dirty check is `getSceneVersion`, a plain *sum* of element versions. Delete an element at version 2, then make two single edits elsewhere: the sum matches the saved one, the tab is marked clean, and close/quit discard the edits with no prompt. A crash snapshot also records "clean", so no recovery is offered. Fix: `hashElementsVersion` (exported; hashes `versionNonce`, which changes on every edit and survives `restoreElement`). |
| BE-1 | 5 | `lib.rs:95` `startup_drawings` | A file name that isn't valid UTF-8 (`caf\xE9.excalidraw` from an old zip or a FAT stick) passed by `%F` makes `std::env::args()` panic. With `panic = "abort"` the app dumps core before it opens a window. **Reproduced** in the release binary (exit 134). On a second launch, the single-instance plugin panics in the same call, so the file is dropped. |
| FE-3 | 4 | `apply.ts:126` | `applyTheme`'s `updateScene` doesn't set `captureUpdate`, so the canvas-colour change is folded into the user's next undo step: switch theme, draw, Ctrl+Z, and the canvas goes back to the old theme's colour. `canvasWasReset` only catches `#ffffff`. |
| FE-2 | 4 | `document.ts:576` `closeTab` | Closing a tab that isn't on screen first switches to it, then lands on *its* successor. With `[A,B,C]` and A showing, × on C leaves you on B, and A's undo history is gone (two scene loads, two `history.clear()`). |
| BE-3 | 4 | `document.ts` `writeTo`, `files.rs` `write_atomic` | Explicit saves to one path aren't serialised. Ctrl+S on a large drawing, then an edit and a second Ctrl+S: the older write can rename last. Ordering reproduced on a copy of `write_atomic`. |
| ST-2 | 4 | `menu.ts`, `App.tsx:209`, `TabBar.tsx`, README | Shortcuts are defined in four places, and they have already drifted. Ctrl+Q is only an accelerator, and Ctrl+N and Ctrl+Tab only exist in the listener. The README says every shortcut is in both. |
| ST-5 | 4 | `api.ts` ↔ `lib.rs` handler list | Nothing checks that the 28 IPC command names and argument names agree. They do today, but a rename would only show up by hand, because the app can't be driven headlessly. |

| BE-7 | 3 | `session.rs:217` | When a drawing's mount (USB, sshfs) is briefly unreachable, the snapshot writes `path: null`. A quit or crash in that window reopens the drawing as untitled. |

| SEC-1 | 3 | `scene.ts:16`, `exports.ts:22` | K1's remote-image filter runs only on load. A pasted `excalidraw/clipboard` payload with an `https:` `dataURL` gets past it, and Save and SVG export then carry the URL. Traced in the bundle. |

Checked and sound (summarised from the reviewers): `Allowed::check` scope and
canonicalisation, `safe_id` everywhere ids become paths, `write_atomic`
(fsync, `create_new`, K3 refusals), the CSP and navigation guard (srcdoc,
blob, embeds), `normalizeLink` on every link, Mermaid at `strict`, PNG-only
clipboard decoding, every mutex recovering from poisoning, no lock held across
an await, `version.mjs` updating all 11 places, and the D1–D5, F1–F4 and V1–V5
fixes from 2026-10-07 all being in place.

--noEmit && npx vite build && cargo test && cargo clippy -D warnings`) and gets
an `/improve-pr` pass before it is opened.

| 7 | Docs | ST-9, PROGRESS | after the rest |

Ordering notes:
- Phase 5 refactors the code that phase 1 fixes, so it is stacked on phase 1
  rather than racing it.
- Phase 6's `cargo fmt` rewrites ten Rust files. It goes in only after phase 2
  has merged, and only when nobody has Rust edits in progress.
- Not planned (score ≤ 2, no data at risk): FE-5, FE-6, FE-7, FE-8, SEC-5's
  Dependabot half, SEC-6. Re-open one if it is ever seen in use.
- Nothing here is seen in a running window. Each PR lists what to check by
  hand on the installed RPM, as earlier reviews did.
