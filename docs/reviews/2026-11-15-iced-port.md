`/code-review` over `git diff main...HEAD` (38 commits, ~32.8k lines). The
code moved from `src-tauri` into `iced/crates/core` behaves as before; the
findings are in the Iced app and one changed fallback in `store.rs`. Ids are
`IR-n`, most severe first.

## How each was dealt with

- **IR-8**: `config_root` asks the password database (`getpwuid_r`) when
  `config_base` rejects `XDG_CONFIG_HOME` and `HOME`, and keeps the answer
  only if it is absolute, else `/`. Tested with `HOME=relative`, `HOME=`
  and no `HOME`.
- **IR-1**: only the recovery question holds handed-over drawings back
  (its answer decides the tabs they join). Behind any other dialog they
  open at once, and the dialog stays on top.
- **IR-5, IR-6**: every error goes through `App::report_error`. It opens
  the error dialog, adds to one already showing, or, behind another kind
  of dialog, waits in `queued_errors` until that closes (`update` shows
  it). A clean start's unreadable snapshots are now reported. This also
  covers async results (export, Save As, import) that used to replace an
  open question.
- **IR-3**: `App.window` starts from the saved state (`Args::saved_window`),
  and `window_state::observed` never takes a maximized size as the normal
  one: it keeps the known size, or the default window size if none is
  known yet.
- **IR-4**: a held item is let go of (`Msg::Cancel`, nothing lands) when
  the pointer leaves the window, the window loses focus, or a dialog comes
  up. On X11 dragging out and back in also cancels; dropping outside the
  window was never supported. Needs a by-hand check on a desktop.
- **IR-10**: an enabled button would take the press before the
  `mouse_area` sees it, so the cell keeps its disabled button and tracks
  hover itself (`on_enter`/`on_exit` into `Library::hovered`). Needs a
  by-hand check on a desktop.
