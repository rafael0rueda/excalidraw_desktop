`/code-review` over `git diff main...HEAD` (38 commits, ~32.8k lines). The
code moved from `src-tauri` into `iced/crates/core` behaves as before; the
findings are in the Iced app and one changed fallback in `store.rs`. Ids are
`IR-n`, most severe first.

## How each was dealt with

- **IR-8**: `config_root` asks the password database (`getpwuid_r`) when
  `config_base` rejects `XDG_CONFIG_HOME` and `HOME`, and keeps the answer
  only if it is absolute, else `/`. Tested with `HOME=relative`, `HOME=`
  and no `HOME`.
- **IR-1**: only the recovery question holds handed-over drawings back
  (its answer decides the tabs they join). Behind any other dialog they
  open at once, and the dialog stays on top.
- **IR-5, IR-6**: every error goes through `App::report_error`. It opens
  the error dialog, adds to one already showing, or, behind another kind
  of dialog, waits in `queued_errors` until that closes (`update` shows
  it). A clean start's unreadable snapshots are now reported. This also
  covers async results (export, Save As, import) that used to replace an
  open question.
- **IR-3**: `App.window` starts from the saved state (`Args::saved_window`),
  and `window_state::observed` never takes a maximized size as the normal
  one: it keeps the known size, or the default window size if none is
  known yet.
- **IR-4**: a held item is let go of (`Msg::Cancel`, nothing lands) when
  the pointer leaves the window, the window loses focus, or a dialog comes
  up. On X11 dragging out and back in also cancels; dropping outside the
  window was never supported. Needs a by-hand check on a desktop.
- **IR-10**: an enabled button would take the press before the
  `mouse_area` sees it, so the cell keeps its disabled button and tracks
  hover itself (`on_enter`/`on_exit` into `Library::hovered`). Needs a
  by-hand check on a desktop.
- **IR-9**: what grew with size is capped where it grows, and
  `MAX_EXTENT` is now 1e9 (beyond it f32 coordinates are too coarse, and
  only damaged files go there):
  - rough's `straight_hachure_lines` scanned once per unit of height and
    drew height / gap lines. Past 10,000 lines or 2,000,000 rows it now
    spaces lines further apart, so a huge filled shape is filled more
    sparsely, not skipped.
  - Dashed strokes: the canvas and tiny-skia cut the whole path into
    dashes, so `render::bounded_dash` stretches the pattern (same
    proportions) to at most 20,000 dashes per path.
  - `render/tests/large_elements.rs` draws every kind, fill and stroke
    style at 1.2e6, 5e7 and 9e8 units: the slowest takes about 3 ms in
    release. rough.js fixtures are unchanged. `fuzz_smoke` gained a 5e8
    value and passes 3 x 20,000 rounds (seeds 1, 7, 42).
- **IR-2, IR-7**: `App::snapshot` only asks for one. Once the message is
  handled, `start_snapshot` copies the changed scenes on the UI thread
  (`session::prepare`) and a thread of its own serializes and writes them
  (`session::write`), one write at a time, with any further request
  coalesced behind it. Each tab counts its changes (`Tab::changes`).
  Only a successful write marks it snapshotted, at the count it was taken
  at, so a change made during the write is still pending. A failed write
  sets the clock to try again. The quit's last snapshot stays
  synchronous and takes `session_ended` first, so a write still in flight
  cannot land after it and undo the clean-exit mark. In tests the write
  runs inline (no runtime to run tasks); a real launch was checked to
  write its first snapshot through the thread.
- **IR-11**: `straight_hachure_lines` also counts the strokes a fill will
  make (the edges' heights over twice the gap; for a convex shape, the line
  count) and spaces lines wider past 50,000. `points_on_bezier_curves`
  shares a budget of 200,000 points among a run's segments: each may be
  halved up to log2(200,000 / segments) times, at most 16. A closed
  2,000-point zigzag, filled, went from 72 s and out of memory (1e6
  units) to 0.1 s and 25 MB; at 10,000 units it was 7.6 million operations
  and is now 200,000. rough.js fixtures are unchanged.
  `large_elements.rs` covers it at 1e4, 1e6 and 9e8 units, every fill.
- **IR-12**: while the link or frame-name editor is open, handed-over
  drawings still open, but the tab being edited stays in view, so the
  answer reaches it. Tested in `tests.rs`.
